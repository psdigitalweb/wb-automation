# Brief Schema — формат входного брифа

Входной бриф — структурированное описание одного SKU, передаваемое в LLM. Формируется из строки Excel-таблицы через pydantic-модель.

---

## Поля брифа

### Обязательные

| Поле | Тип | Описание |
|------|-----|----------|
| `sku` | str | Уникальный артикул в рамках кабинета WB (используется как ключ для чекпоинтов) |
| `товар` | str | Короткое название предмета, как в предметной категории WB. Пример: «рюкзак женский городской» |
| `категория_wb` | str | Точное название предмета в классификаторе WB. Пример: «Рюкзаки» |
| `ключевые_факты` | list[str] | Список фактических характеристик: материал, размер, особенности. 3–10 строк |
| `комплектация` | str | Что лежит в упаковке. Пример: «рюкзак, фирменный мешочек» |
| `главная_боль_покупателя` | str | Одна самая частая жалоба/страх из отзывов на аналоги. Нужна для блока 2 описания |
| `сценарии_использования` | list[str] | 2–4 конкретных сценария. Пример: «дорога на работу в офис» |
| `целевая_аудитория` | str | Кому это конкретно. Пример: «женщины 25–40, офис/удалёнка» |
| `семантика` | object | Семантическое ядро. Структура ниже |
| `голос_бренда` | enum | Один из: `экспертный`, `тёплый`, `минималистичный`, `игривый` |

### Опциональные

| Поле | Тип | Описание |
|------|-----|----------|
| `не_входит` | str | Что покупатели ожидают увидеть, но этого нет. Если не указано — блок «что не входит» в описании пропускается или заполняется по умолчанию |
| `доп_бренд_контекст` | str | 1–2 фразы о бренде: из чего делаем, принцип |

### Структура поля `семантика`

```yaml
семантика:
  вч: [строки]              # 2–3 ВЧ-запроса (5000+ показов/мес)
  сч: [строки]              # 5–10 СЧ-запросов (1000–5000 показов)
  нч: [строки]              # 5–15 НЧ-запросов (до 1000 показов)
  околотематика: [строки]   # 3–5 смежных кластеров
```

Все списки могут быть пустыми, но хотя бы один из `вч`/`сч` должен содержать элементы — иначе генерация бессмысленна, валидатор отклонит бриф на этапе загрузки.

## Pydantic-модель (эталонная)

```python
from enum import Enum
from pydantic import BaseModel, Field, field_validator


class BrandVoice(str, Enum):
    EXPERT = "экспертный"
    WARM = "тёплый"
    MINIMAL = "минималистичный"
    PLAYFUL = "игривый"


class Semantics(BaseModel):
    vch: list[str] = Field(default_factory=list, alias="вч")
    sch: list[str] = Field(default_factory=list, alias="сч")
    nch: list[str] = Field(default_factory=list, alias="нч")
    okolo: list[str] = Field(default_factory=list, alias="околотематика")

    @field_validator("vch", "sch")
    @classmethod
    def strip_items(cls, v: list[str]) -> list[str]:
        return [item.strip() for item in v if item.strip()]

    def total(self) -> int:
        return len(self.vch) + len(self.sch) + len(self.nch) + len(self.okolo)

    model_config = {"populate_by_name": True}


class Brief(BaseModel):
    sku: str
    tovar: str = Field(alias="товар")
    kategoria_wb: str = Field(alias="категория_wb")
    key_facts: list[str] = Field(alias="ключевые_факты")
    komplektatsia: str = Field(alias="комплектация")
    ne_vhodit: str | None = Field(default=None, alias="не_входит")
    glavnaya_bol: str = Field(alias="главная_боль_покупателя")
    stsenarii: list[str] = Field(alias="сценарии_использования")
    target: str = Field(alias="целевая_аудитория")
    semantika: Semantics = Field(alias="семантика")
    golos_brenda: BrandVoice = Field(alias="голос_бренда")
    dop_brend_kontekst: str | None = Field(default=None, alias="доп_бренд_контекст")

    @field_validator("key_facts", "stsenarii")
    @classmethod
    def non_empty(cls, v: list[str]) -> list[str]:
        cleaned = [item.strip() for item in v if item.strip()]
        if not cleaned:
            raise ValueError("список не может быть пустым")
        return cleaned

    model_config = {"populate_by_name": True}
```

## Excel-формат (input/briefs.xlsx)

Одна строка = один SKU. Колонки строго в таком порядке:

| Колонка | Тип | Формат заполнения |
|---------|-----|-------------------|
| `sku` | текст | артикул |
| `товар` | текст | короткое название |
| `категория_wb` | текст | из классификатора WB |
| `ключевые_факты` | текст | элементы через `;` или `\n` |
| `комплектация` | текст | через запятую |
| `не_входит` | текст (опц.) | через запятую |
| `главная_боль_покупателя` | текст | одно предложение |
| `сценарии_использования` | текст | элементы через `;` |
| `целевая_аудитория` | текст | одно предложение |
| `вч` | текст | запросы через `;` |
| `сч` | текст | запросы через `;` |
| `нч` | текст | запросы через `;` |
| `околотематика` | текст | запросы через `;` |
| `голос_бренда` | текст | один из 4 вариантов |
| `доп_бренд_контекст` | текст (опц.) | одно-два предложения |
| `статус` | текст | заполняется генератором: `pending`/`ok`/`failed` |

## Как бриф встраивается в системный промпт

Парсер клиента OpenRouter формирует `user`-сообщение как YAML-блок:

```
Вход:

```yaml
товар: "..."
категория_wb: "..."
...
```

Сгенерируй карточку по правилам системного промпта.
```

Системный промпт (`prompts/system_prompt.md`) передаётся в поле `system` и кэшируется. На каждый SKU меняется только `user`-сообщение с брифом (~400 токенов).
